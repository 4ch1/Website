# Модуль 10. Торговый план и журнал

> Что здесь: два документа, без которых всё предыдущее не работает. План на день — чтобы решения принимались до открытия, а не в 09:31. Журнал — чтобы через 100 сделок знать, а не чувствовать, что работает. Шаблоны лежат в `course/templates/`.

## 10.1. Зачем это инженеру

Торговля без плана и журнала — это код без тестов и логов в продакшене. Всё, что вы «знаете» о своих результатах, искажено памятью: прибыльные сделки помнятся, убыточные забываются (модуль 11). Журнал — единственный источник правды. Статистика из журнала — единственное основание менять правила.

Тренажёр ведёт свой журнал автоматически (SQLite, см. README). Для реальных сделок придётся вести руками или скриптом. Формат ниже совместим с тем, что считает тренажёр.

## 10.2. План на день (daily plan)

Заполняется **до 09:25 ET**, занимает 10–15 минут. Шаблон: `templates/daily-plan.md`.

```markdown
# План на {{дата}}

## 0. Состояние
- Сон: ___ ч. Самочувствие (1–5): ___. Если < 3 — не торгую.
- Результат вчера: ___R. Серия: ___ (если 3 стопа подряд → размер 0.5R).
- Неделя: ___R из лимита −5R. От пика: ___R из лимита −10R.

## 1. Рынок (D)
- SPY/QQQ: тренд по EMA20 ___ ; закрытие вчера относительно PDH/PDL ___ ; фьючерсы на премаркете ___ %.
- События сегодня (время ET): ___ (CPI 08:30 / FOMC 14:00 / отчёты ...). В ±15 мин вокруг — не торгую.

## 2. Инструменты (максимум 3)
| Тикер | D тренд | 15m структура | PDH / PDL / PDC | PMH / PML | ключевые D-уровни | гэп (ATR) |
|---|---|---|---|---|---|---|
| | | | | | | |

## 3. Гипотеза дня (одна строка на тикер)
- SPY: «гэп вверх над PDH, 15m HH/HL → ищу gap and go или ретест PDH; шорт только после CHoCH на 15m».

## 4. Разрешённые сетапы сегодня
- [ ] ORB  [ ] gap and go  [ ] gap fill  [ ] VWAP reclaim/reject  [ ] пробой-ретест  [ ] fakeout  [ ] разворот от уровня
- Только в первые 90 минут: ___. После 11:00 — только: ___ (или ничего).

## 5. Риск
- R = $___ (___% капитала). Макс. сделок: 3. Дневной лимит: −2R (выставлен у брокера: да/нет).
- Размер при конфликте D/15m: 0.5R.

## 6. Правила остановки на сегодня
- 2 стопа → стоп торговли. 1 сделка без плана → стоп торговли. Эмоция «отыграться» → закрыть платформу.

## 7. Итог дня (заполняется в 16:05)
- Сделок: ___. Результат: ___R. Лимиты соблюдены: да/нет. Сделки без плана: ___.
- Одна вещь, которую сделаю лучше завтра: ___.
```

Что в этом плане главное:

- **Гипотеза дня в одну строку.** Если она не формулируется, торговать нечего.
- **Список разрешённых сетапов.** Не «что увижу», а «что жду». Сделка вне списка — нарушение, даже если прибыльная.
- **Пункт 0.** Сон меньше 6 часов и самочувствие ниже 3 коррелируют с худшими решениями сильнее любого индикатора; это самый дешёвый фильтр.

## 10.3. Запись сделки (trade record)

Одна строка на сделку. Заполняется в два приёма: план **до** входа (колонки 1–14), факт **после** выхода (15–24). Шаблон: `templates/trade-journal.csv`.

| # | Поле | Пример | Зачем |
|---|---|---|---|
| 1 | date | 2026-10-15 | |
| 2 | ticker | SPY | статистика по тикеру |
| 3 | setup | level_reversal | тег из модуля 7 (orb, gap, vwap, break_retest, fakeout, level_reversal, other) |
| 4 | direction | long / short | |
| 5 | timeframe | 5m | |
| 6 | time_entry | 09:52 | статистика по времени дня |
| 7 | day_type_forecast | trend_up | оценка на момент входа (модуль 7.7) |
| 8 | align_d / align_15 | yes / no | согласие с D и 15m (модуль 8) |
| 9 | level | PDH 769.0 | уровень, у которого сетап |
| 10 | rvol | 1.8 | объём на баре сигнала |
| 11 | entry / stop / target | 769.20 / 768.70 / 770.20 | план |
| 12 | rr_planned | 2.0 | |
| 13 | risk_usd | 150 | R в долларах |
| 14 | shares | 300 | = risk / (entry − stop) |
| 15 | exit_price / time_exit | 770.20 / 10:14 | факт |
| 16 | exit_reason | target / stop / time / manual | «manual» — повод для разбора |
| 17 | result_r | +2.0 | (exit − entry) × shares / risk_usd |
| 18 | mfe_r / mae_r | +2.3 / −0.4 | макс. ход в плюс и в минус за время сделки, в R: показывает, где стоп и цель были «неправильными» |
| 19 | day_type_actual | trend_up | факт по закрытию (модуль 7) |
| 20 | plan_compliance | A / B / C | A — всё по плану; B — отклонение в исполнении; C — сделка вне плана |
| 21 | mistakes | late_entry, moved_stop, early_exit, fomo, revenge, size | теги ошибок (модуль 11) |
| 22 | screenshot | 2026-10-15_SPY_0952.png | график 5m в момент входа и после выхода |
| 23 | note | «вошёл на второй свече, не на первой» | одна фраза |
| 24 | grade_setup | 1–5 | качество сетапа *независимо* от результата |

Два поля, которые меняют всё: **plan_compliance** и **grade_setup**. Хорошая сделка — это сделка по плану с качественным сетапом, **а не прибыльная сделка**. Прибыльная сделка класса C (вне плана) — худшее, что может случиться с новичком: она закрепляет нарушение.

## 10.4. Что считать из журнала и когда

Минимум раз в неделю, по CSV:

```python
import pandas as pd
j = pd.read_csv("trade-journal.csv")
print("expectancy, R:", j.result_r.mean().round(3), "| сделок:", len(j), "| win rate:", (j.result_r > 0).mean().round(2))
print(j.groupby("setup").result_r.agg(["count", "mean"]).round(2))          # по сетапам
print(j.groupby(j.time_entry.str[:2]).result_r.agg(["count", "mean"]).round(2))  # по часам
print(j.groupby("plan_compliance").result_r.agg(["count", "mean"]).round(2)) # A vs B vs C
print(j.groupby("align_d").result_r.agg(["count", "mean"]).round(2))         # фильтр старшего ТФ
print("MFE медиана у стопов:", j[j.exit_reason == "stop"].mfe_r.median())    # сколько сделки «давали» до стопа
```

Разрезы, которые дают больше всего:

| Разрез | Вопрос | Решение при ответе |
|---|---|---|
| по plan_compliance | сделки C прибыльны? | если да — это удача, запрет сохраняется; если нет — очевидно |
| по времени входа | 11:00–13:00 в минусе? | запретить это время |
| по сетапу | один сетап тянет всё? | убрать остальные на месяц |
| по тикеру | один тикер стабильно хуже? | убрать |
| MFE у стопов | медиана MFE ≥ 1R? | частичная фиксация на 1R |
| MAE у целей | медиана MAE < 0.3R? | стоп можно сократить (но не ближе 0.5 ATR) |
| серия после 2 стопов | третья сделка дня прибыльна? | лимит −2R подтверждён |

Правило изменения правил: любое изменение системы — только по данным ≥ 50 сделок в разрезе и только одно изменение за раз. Иначе через месяц вы не узнаете, что сработало. Что такое «достаточно сделок» статистически — модуль 12 и панель тренажёра.

## 10.5. Еженедельный разбор (30 минут, выходные)

1. Таблица недели: сделок, R, лимиты, сделки C.
2. Три лучшие сделки по grade_setup (не по результату): что общего.
3. Три худшие по plan_compliance: какая ошибка, какой триггер (модуль 11).
4. Один разрез из таблицы выше.
5. Одно изменение на следующую неделю (или ни одного).
6. 20 раундов в тренажёре по слабому сетапу.

## Типичные ошибки

1. Журнал «в голове» или только в выписке брокера (там нет сетапа, плана и ошибок).
2. Записывать только результат. Результат — наименее информативное поле.
3. Оценивать сделку по прибыли, а не по соблюдению плана.
4. Менять правила после 5 сделок.
5. Менять три правила сразу.
6. План «в целом»: без гипотезы дня и списка сетапов.
7. Не записывать сделки, за которые стыдно. Это ровно те, которые нужны.

## Мини-тест

1. Зачем в плане пункт о сне и самочувствии?
2. Что такое гипотеза дня и что делать, если она не формулируется?
3. Чем «хорошая сделка» отличается от «прибыльной сделки»?
4. Что показывают MFE и MAE и какие решения на них основаны?
5. Сколько сделок нужно в разрезе, чтобы менять правило, и сколько правил менять за раз?
6. Что такое сделка класса C и почему прибыльная сделка C опасна?
7. Какие поля заполняются до входа, какие после?
8. Какой разрез журнала проверяет лимит «−2R в день»?
9. Что делать с разрезом «по времени входа», если 11:00–13:00 в минусе на 60 сделках?
10. Почему выписки брокера недостаточно как журнала?

### Ответы

1. Сон < 6 ч и самочувствие < 3 ухудшают решения сильнее любого рыночного фактора; это бесплатный фильтр, который убирает худшие дни.
2. Одна строка: контекст → что жду → что запрещено. Если не формулируется — торговать нечего, день пропускается.
3. Хорошая — по плану (compliance A) с качественным сетапом (grade ≥ 4), независимо от результата. Прибыльная может быть классом C.
4. MFE — максимальный ход в плюс, MAE — в минус за время сделки, в R. MFE у стопов ≥ 1R → частичная фиксация на 1R; MAE у целей < 0.3R → можно сократить стоп (не ближе 0.5 ATR).
5. ≥ 50 сделок в разрезе; одно изменение за раз.
6. Сделка вне плана. Прибыль закрепляет нарушение, и следующие сделки C будут убыточными при уже сформированной привычке.
7. До входа: сетап, направление, время, тип дня, согласие с D/15m, уровень, RVOL, вход/стоп/цель, R:R, риск, размер. После: выход, причина, результат, MFE/MAE, факт типа дня, compliance, ошибки, скриншот, оценка.
8. Результат третьей сделки дня после двух стопов (и результат дня после −2R, если лимит нарушался).
9. Запретить вход в это время; это первое и самое надёжное из решений по журналу.
10. В выписке нет сетапа, плана, стопа, причины выхода, ошибок и оценки, то есть ничего, что нужно для улучшения.
