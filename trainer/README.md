# Тренажёр «куда пойдёт цена»

Локальное веб-приложение: показывает кусок реального интрадей-графика (SPY, QQQ, IWM и крупные акции), обрывает его в случайной точке, вы делаете прогноз (вверх / вниз / флэт на N свечей), опционально ставите вход, стоп и цель прямо на графике, затем следующие свечи раскрываются с анимацией, и показывается результат прогноза, сделки в R и алгоритмический разбор по правилам [курса](../course/README.md).

## Запуск одной командой

```bash
cd trainer
make run          # создаст .venv, поставит зависимости, соберёт фронтенд, скачает данные (первый раз ~1 мин), запустит http://127.0.0.1:8000
```

Нужны: Python ≥ 3.11, Node ≥ 18 (для сборки фронтенда), `make`. `uv` используется, если установлен, иначе `pip`.

Другие команды: `make test` (pytest), `make e2e` (Playwright, на фикстурных данных без сети), `make refresh` (дописать свежие бары в кеш), `make figures` (перестроить картинки курса), `PORT=9000 make serve`.

Без `make`: `uv venv .venv && uv pip install -e ".[dev]" && (cd frontend && npm install && npm run build) && .venv/bin/python -m backend.cli fetch && .venv/bin/uvicorn backend.main:app`.

## Данные

- Провайдер по умолчанию — **yfinance** (без ключа): 1m за последние 30 дней (Yahoo отдаёт по 7 дней за запрос), 5m за 60 дней, дневные за 2 года. Кеш в `data/cache/*.parquet`, **накопительный**: каждый `make refresh` дописывает новые дни, история растёт.
- Опционально **Alpaca** (бесплатный ключ, IEX-фид, 1m за несколько лет): `TRAINER_PROVIDER=alpaca ALPACA_KEY=… ALPACA_SECRET=… make refresh`.
- Тикеры: `TICKERS=SPY,QQQ make data` или переменная `TRAINER_TICKERS`.
- Честно про качество бесплатных данных: в 1m-объёме Yahoo встречаются одиночные «комки» в 50–300 раз больше медианы, сумма объёма по 5m-барам не сходится с дневным объёмом, в премаркете бывают плохие тики. В коде объём винзоризуется каузально (не больше 8× медианы предыдущих 30 баров той же сессии; 4× для VWAP), тени длиннее 5% цены обрезаются. Для серьёзной работы с объёмом нужен платный фид.

## Без lookahead

- Раунд строится как `visible = bars[:cutoff+1]`; индикаторы, уровни, структура, паттерны и сетапы считаются **только по видимой части** (`backend/engine/markup.py`). Скрытые бары хранятся на сервере и возвращаются только методом reveal вместе с результатом.
- Каждая функция фич каузальна: тест `tests/test_no_lookahead.py` проверяет prefix-инвариантность (`f(bars[:k]) == f(bars)[:k]`), свинги и фигуры несут `confirmed_at`, детекторы на префиксе дают те же события, что на полном ряду с `idx < k`. `tests/test_engine.py` и `tests/test_api_stats.py` проверяют, что ответ API не содержит баров позже точки обрыва, а reveal возвращает ровно N баров после неё.

## Механика

- Порог флэта: `k · ATR14(cutoff) · √N` (k по умолчанию 0.35, настраивается). Исход — по закрытию N-й скрытой свечи.
- Сделка: тип входа выводится из цены (выше рынка для лонга — stop-ордер, ниже — limit, пусто — market по открытию следующего бара); исполнение по касанию; стоп и цель в одном баре — считается стоп; без выхода за N баров — закрытие по последней свече. Результат в R, плюс MFE/MAE.
- Режимы: **экзамен** (случайные точки, без подсказок), **обучающий** (точки обрыва — бары, на которых сработал сетап или фигура из курса, с подсказками и чек-листом советника), **по теме** (только выбранный сетап: ORB, гэпы, VWAP, пробой-ретест, fakeout, разворот от уровня, флаги, треугольники, двойные вершины).
- Опция «скрыть тикер и дату» (по умолчанию включена; время дня остаётся видно).
- Разбор: структура (HH/HL, BOS/CHoCH), уровни, свечные и графические паттерны, сетапы, климакс-объём, оценка и факт типа дня, профиль объёма видимой сессии, и «решение по правилам курса» (советник: действие, план входа/стопа/цели, чек-лист фильтров, результат его плана на скрытых барах).

## Статистика (SQLite, `data/trainer.sqlite`)

Точность в целом, по тегам, по часу дня, по тикеру, по режиму; интервал Уилсона; базовые линии: монетка (1/3), «всегда по тренду» (VWAP + наклон EMA20), самый частый класс, советник курса; биномиальные тесты (p-value, односторонние) против каждой; матрица ошибок; expectancy в R, доля прибыльных, 95% ДИ, t-тест, equity curve, максимальная просадка; **минимальное число раундов** для статистически осмысленного вывода при текущей точности (α = 0.05, мощность 0.8) показывается явно.

## Структура

```
backend/
  data/      провайдеры (yfinance, Alpaca), parquet-кеш (+CSV fallback), сессии
  features/  indicators, levels, structure, candles, patterns, setups, volume — всё каузальное
  engine/    rounds (выборка/окно/reveal), outcome, trade, markup, advisor
  stats/     статистика; db/ SQLite; main.py FastAPI (/api/config, /api/round, /api/round/{id}/answer, /api/stats, /api/history)
frontend/    Vite + TypeScript + lightweight-charts (без фреймворка)
tests/       pytest (lookahead, исходы, R, детекторы, API, статистика); fixtures — замороженные реальные бары
e2e/         Playwright (поднимает сервер на фикстурах)
```

Переменные окружения: `TRAINER_DATA_DIR`, `TRAINER_DB`, `TRAINER_TICKERS`, `TRAINER_PROVIDER`, `TRAINER_SEED`.
